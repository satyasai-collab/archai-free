# Аудит архитектуры ArchAI Free — 2026-08-23

Read-only аудит действующей multi-role архитектуры (opencode + Hermes,
free-модели). Ничего не исправлено — фиксируем состояние как есть.

## 1. SPOF: единый канал Expert (критично)

Вся дисциплина (opencode `task(expert)` И Hermes delegation) замкнута на один
локальный сервер `127.0.0.1:8000` с одним аккаунтом. Мьют аккаунта длился
23 часа — все многошаговые задачи встали (`[EXPERT BLOCK]`, fallback запрещён
протоколом). Отказоустойчивости нет by design.

## 2. Конкуренция за единственный слот

opencode и Hermes бьют в одну обёртку одновременно; лок отдаёт мгновенный 429
без очереди. Параллельная работа двух клиентов = взаимные отказы.
Retry-After 3с не спасает при реальной нагрузке.

## 3. Три источника правды, рассинхрон

- Инструкция двухмодельной архитектуры описывала мёртвую схему: curl-канал,
  старый репо-обёртку, правило «Expert БЕЗ исключений» — прямо противоречит
  действующему Правилу 1 итерации.
- Конфиг одного из стеков указывал устаревшую модель Executor'а.
- AGENTS.md / EXPERT_PROTOCOL.md / MEMORY.md / SOUL.md дублируют роли — каждое
  изменение правил приходится накатывать в 4 файла, что уже приводило к дрейфу.

## 4. Монитор снижает собственную гарантию

TTL 60с в `expert_monitor.ts` авто-снимает блокировку и сбрасывает счётчик БЕЗ
вердикта эксперта — легальный обход MUT-1: достаточно подождать минуту. Плюс
сброс счётчика по самому факту `task(expert)` — можно «накрутить» пустым
вызовом.

## 5. Enforcement — только текстом

Жёсткие гарантии (Expert обязателен, критик = HARD STOP) живут в
markdown-промтах; единственный механический барьер — плагин со счётчиком,
обходящийся маркером и TTL. Гарантия держится на добросовестности модели,
которую эта схема и должна ловить.

## 6. Хрупкий free-tier в двух критичных ролях

Основная модель и критик — бесплатные модели с задокументированными флаками
(200/503/500, 429-квоты, GARBAGE у критика из-за reasoning). Бюджет критика
≤2 вызова → частые `[CRITIC BLOCK]` → эскалация вместо проверки.

## 7. Конфигурация без версионирования

Рабочие директории конфигов — не git-репозитории. История изменений — только
ручные `.bak`-копии (7+ штук). Ни diff-аудита, ни единого механизма отката.

## 8. Прочее

- Глобальный `max_tokens: 2000` — для reasoning-моделей даёт пустой content,
  для длинных отчётов мало.
- Секреты и состояние рядом с конфигами: auth.json, браузерные session-куки.
- ~470 МБ tar.gz-бэкапов в домашней директории вперемешку с рабочими файлами.
